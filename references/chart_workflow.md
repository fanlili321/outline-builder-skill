# 模式A配图规范

大纲阶段的配图任务：钉大/用户在飞书大纲文档里批注 @AI，本技能出图并插回文档。图是**示意图**（静态PNG），正式PPT阶段会重新做——所以大纲图追求"数据对、规范严、快"，不追求可编辑。

## 需求分流（第一步，两套标准绝不混用）

每条 @AI 批注先判断类型，再走对应分支（用户明确要求：两类图标准不同、不能混）：

| 信号 | 类型 | 分支 |
|---|---|---|
| 指数/基金名称＋走势/回撤/星级/涨跌幅/时间区间 | **走势图**（数据图） | 走势图分支（Wind取数+matplotlib） |
| "设计页""三个框可视化"、要点/流程/对比示意、书籍观点提炼 | **设计图**（版式图） | 设计图分支（PIL+设计规范） |

- 一条批注同时要两类图 → 拆开分别走各自分支。
- 批注模糊（如只写"@AI 配个图"）→ **问用户**，不瞎猜。
- **但批注是探索性语气**（如"用AI试试看可视化"）**时不要停下来反问，直接做一版给用户看**：自己选合理的数据源/指数/区间/口径，把这些假设清楚写在图内小字和回复里，等用户看了实物再调整（468期"按日/按周/按月定投，效果差不多"就是这么处理的，一次做对，没有被打回）。"试试看"和"配个图"的区别在于前者已经默许了AI自主判断的空间。
- 回复用户时**逐条说明每个批注被归为哪类**，让用户能发现路由错误。

## 铁律（两类图通用，用户明确要求过的）

1. **只出图，不改大纲任何文字。** 发现明显笔误（如"跑赢"应为"跑输"）也只在回复里汇报，等用户确认后改**图内标题**，大纲文字仍不动。
2. 批注里除了 @AI 还有给钉大的说明（换指数、换口径、数据待提供、样式待确认等），**出图时要一并遵守**；"待提供/待复核"的内容在图内小字注明并在回复里提醒。
3. 样式有"待确认"项时**两版都出**，caption标清「样式一/样式二」让钉大选。
4. 每张图的飞书caption统一为：**「图片来自AI，仅供示意，ppt中会重新作图，并核对数据」**。两版样式图加「样式一（…）｜」前缀。
5. 改图 = 删旧图块再重插（或只改caption），**不留旧版本**在文档里（只处理AI插的图；团队手动贴的图不要擅自删，先问）。
6. **每轮改图前必须重新拉最新 blocks**：文档随时被钉大/团队编辑（改H3、改展示句、删图），上一轮的锚点文字和块ID可能已失效。锚点匹配失败=文字被改了，去最新文档找对应新句子，图内标题同步对齐最新H3（458期实测发生过）。

## 通用流程

1. **读大纲和批注**：用 lark-cli（全部命令见 [references/feishu_ops.md](references/feishu_ops.md)）。`raw_content` 读全文；comments 接口读批注（`quote`=锚点原句，replies含`@AI`的才是任务）；附件（星级xlsx等）medias download 下载，内部数据优先用附件。
2. **按分流结果产图**（见下面两个分支）。
3. **插回文档**：`lark-cli docs +media-insert --selection-with-ellipsis "锚点原句"` 插到批注句正下方；同一锚点多张时**后插的在前**；插完重拉 blocks 核验（前一块是锚点、image token 绑定成功）。**锚点文字含中文引号或是较长整句时容易匹配失败**（直引号/弯引号不一致、或触发 shell 转义问题）；改用一段不含标点、更短的唯一子串定位更稳（468期实测：整句带弯引号报"未找到匹配内容"，换成十来个字的无标点子串一次命中）。
4. **收尾**：成图＋脚本＋数据缓存备份到 `Desktop/范丽丽./live-ppt-tool/outline_NNN/`（持久文件不放Downloads）；回复里每张图一句要点＋主动汇报发现的问题（笔误、数据反常、口径缺失），只报不改；新验证的指数代码更新进记忆 reference-live-index-codes。

## 走势图分支（数据图：matplotlib + Wind）

### 取数
- 指数代码**先查记忆 reference-live-index-codes**（已验证清单，含全收益/价格版区分）。已证实：创业板指全收益=创业板R=`399606.SZ`
- 取数用 `live_helpers.kl(code, 'YYYY-MM-DD', 'YYYY-MM-DD', 'D')`（`sys.path` 加 `/Users/fanlili/Desktop/范丽丽./live-ppt-tool`），按年分段自动重试
- 数据存 JSON 缓存再画图，避免改样式时重复取数
- 合理性检查：全收益≥价格版、涨跌幅与常识相符；反常就换代码验证，别硬画

#### 取不到数时怎么办（471期实录，这一节全是踩过的坑）

**铁律：数据源挂了/没覆盖，只如实报告并给选项，绝不拿口径相近的数糊弄过去。** 宁可这张图不出，也不能出一张数据来路不明的图。

- **先做对照测试，区分"接口坏了"还是"这个标的没有"**：拿一个**早先能用的查询**再跑一次。471期Wind宏观库中途返回"权限不足"，用之前正常的 LPR(M0331299)、10年期国债(M1001654) 复测同样报错 → 判定是权限/额度问题，不是查询写法问题。反过来，查中证REITs股息率返回 null 时，用沪深300跑同一个调用返回 2.59% 正常 → 判定是**该标的没有这个字段**（REITs是基金不是股票，不在Wind股票指数估值框架里，股息率/PE/PB 全 null），不是接口故障。
- **Wind 有字段盲区**，`analytics_data` 也补不了（契约允许在专项工具无覆盖时兜底，但471期实测同样"没找到数据"）。别反复换问法硬试，两三次无果就换源或报告。
- **官网数据接口比页面好用**：页面用 React/Nuxt 时，日期选择器、查询按钮往往驱动不了（`form_input` 填了值组件状态不认）。通法是 `navigate` → `read_network_requests` 找真实 API → 直接 `fetch`。471期中原地产 CCL 就是这么拿到的：页面点不动，但 `/CCI/api/Index/CCLChart` 一次返回 1993年至今 1707 个周度点。中证指数公司的"指数估值"其实是个 `.xls` 下载链接（`oss-ch.csindex.com.cn/.../{code}indicator.xls`），直接 curl + pandas 解析。
- **滚动窗口的数据源补不了历史，要早识别**：中证REITs估值文件只保留**最近20个交易日**，发一天冲掉一天。这类源从现在开始每天抓也只能攒未来的，2021年基准日以来的历史永远拿不回（Wayback 也确认零存档）。识别出来就立刻告诉用户"这条路不成立"，别让他等。
- **自然语言取数接口会静默出错，必须逐条校验**（iFinD `get_edb_data` 实录，三类错误一次全踩到）：
  1. **换主体**——问「常德」返回「漳州」
  2. **换指标**——问「租金回报率」（诸葛/二手房口径）返回「租金收益率:住宅」（同花顺口径），两者差0.5个百分点以上
  3. **漏主体**——问4个城市返回3个
  → 做法：**逐个主体单独查**，拿到结果核**主体名/指标名/数据源**三项，任一不符就丢弃并记为缺失，**绝不用返回的替代品凑数**；收尾如实报告每档实际覆盖数（如"三线35城只取到22个"），覆盖太少就说清代表性不足，不照画。
- **同名指标不同口径，混用即废数**：北京"租金收益率"三个值——Wind住宅口径 2.21%、Wind二手住宅口径 1.62%、iFinD诸葛口径 2.03%。做分档平均前必须确认**所有城市来自同一口径同一数据源**，metadata 里的 `data_source` 要逐个核。

### 画图
用 [scripts/chart_helpers.py](../scripts/chart_helpers.py)（配色/字体/坐标轴/图例/来源标注已封装）。核心样式（与PPT一致，钉大看惯了这套，不一致会被打回）：
- 思源黑体；主色橙#F17640、浅蓝#7CA7E0、灰#929292；星级线加深金黄#E5A200走副轴
- 图例横排靠左置顶；Y轴百分比整数刻度＋浅灰横网格；X轴 `YYYY.M` 格式4-7个刻度
- **字号统一走 `chart_helpers` 常量，不要写死数字**（471期用户连提三次"放大"后定的档位，原因是这套图最终投直播大屏，旧字号在屏上普遍偏小）：
  | 用途 | 常量 | 字号 | 旧值 |
  |---|---|---|---|
  | 图表主标题 | `TITLE_SIZE` | 32 | 26 |
  | 横纵坐标刻度、轴标签 | `TICK_SIZE` | 20 | 15 |
  | 图例 | `LEGEND_SIZE` | 20 | 15 |
  | 副轴刻度/轴标签 | `TICK_SIZE_2ND` | 18 | 14 |
  | 图下方数据表 | `TABLE_SIZE` | 18 | 14.5 |
  | 底部来源注/口径注 | `SRC_SIZE` | 16 | 12 |
  `base_chart()`/`pct_axis()`/`fmt_xaxis()`/`add_right_axis()`/`add_source()`/`add_table()` 已内置；**自己写 `set_title(fontsize=…)`、`tick_params(labelsize=…)`、`set_yticklabels(fontsize=…)`、`legend(fontsize=…)`、`fig.text(fontsize=…)` 时一律引用常量**，否则以后调一次要满文件找（471期就因为字号散落在5个脚本里，返工重跑了一遍）。
- **放大字号后必须重新目检每张图**：字号变大容易把图例挤出画布、把标题撑到换行、或让 X 轴首尾刻度落到 `xlim` 之外被切掉（471期CCL图起点是2006年，放大后X轴第一个标签却变成2008，就是 `set_xlim(days[0], …)` 卡在首个刻度之后导致的；把 xlim 往外放一点即可）。
- 多线**按共同交易日对齐**归一化为相对首日涨跌幅（绝不断线）
- **右下角灰色来源标注**（必加，用 `add_source()`，两套口径按图表内容二选一，不能混用/自造）：
  - **指数/行情类图表（默认）**：只写「数据来源：Wind」；图里带螺丝钉星级/估值表才追加成「Wind、银行螺丝钉」（`add_source(..., star=True)`）。
  - **投顾组合净值类图表**（如"主动优选""指数增强"等组合走势，数据来自 dbms.yhlsd.com 螺丝钉数据工具箱）：固定来源是「东方证券、雪球基金」（`add_source(..., portfolio=True)`），不写Wind打底；图里如果还叠了Wind取的数据（如对比基准指数），在前面加"Wind、"（`wind=True`）；图里带螺丝钉星级，在后面加"、银行螺丝钉"（`star=True`）。四种组合示例：仅组合净值→"东方证券、雪球基金"；组合净值+Wind指数→"Wind、东方证券、雪球基金"；组合净值+星级→"东方证券、雪球基金、银行螺丝钉"；三者都有→"Wind、东方证券、雪球基金、银行螺丝钉"。
  - 来源一律不写"螺丝钉团队"这个说法（470期教训：曾经默认加了"螺丝钉团队"，被用户纠正）。
  - 口径特殊时左下角用 `note` 参数加注。
- 图内标题用大纲 H3 原文
- 星级叠加图、月度涨跌幅表格图现成写法：`live-ppt-tool/outline_458/render_458.py`

**每张图渲染后必须 Read 目检**：文字不截断、图例不压线、标注不压轴、走势和结论说得通。

## 设计图分支（版式图：PIL + 设计规范）

### 验收权威标准
用户的《AI生成直播PPT图片规范》，全文在 [references/design_spec.md](references/design_spec.md)，**出设计图前先读它**。核心四条（图在手机直播界面上半屏展示，钉大按"小屏缩略图"验收）：
1. **小屏可读**：缩到手机屏1/3高度后一眼懂主题、关键文字数据看得清。
2. **单页一个核心观点**：最多2-3个短要点或1个主图表+1句结论；内容多就拆页。
3. **字号下限**（1920x1080）：主标题≥64px、正文要点/结论≥48px、图表标签≥28-32px；来源注等边角小字可小但不能是必读内容。
4. **去装饰化**：删一切无信息含义的图标（人物/奖杯/金币/楼房/星星/箭头/贴纸/边框/插画/拟物图）。每个元素只问：它是否直接帮助观众理解本页结论？不能就删。
5. **要有真图形逻辑，不是排版好看的文字块**（470期教训：用户反馈"为啥你做的可视化只有文字"）。因果链/流程用 `right_arrow`/`flow_arrow` 连起来，占比用比例条画出来，涨跌用 `direction_triangle`（配 ORANGE=涨/BLUE=跌）画出来，阈值分档用色块深浅画出来——凡是大纲原文能直接提炼出"顺序、比例、方向、层级"这类结构的，都要用图形把结构画出来，不能只是把这句话原样搬进卡片里当"可视化"。

### 提炼内容（设计图的"取数"）
原材料是大纲文字：从批注和对应 H3 段落提炼**一个核心观点＋最多2-3个短要点/关键数据**。大纲原文通常太长，大幅压缩成短句但**不得改变事实口径**，压缩后的表述在回复里让用户核对。数字是关键数据要做大做醒目。

### 渲染与小屏验收
用 [scripts/design_helpers.py](../scripts/design_helpers.py)（画布/字体/配色/组件/字号校验/缩略图已封装）：
- 思源黑体；主色橙#F17640、卡片底#FDF0E7、正文#333、灰#8A8A8A、辅助蓝#7CA7E0（跟橙色搭配区分"另一个方向"，如跌/减少 对比 涨/增加，不用红绿）
- 常用版式：`stat_card` 数据大字报、`tight_box` 紧贴文字的框（纵向流程步骤）、`right_arrow`/`flow_arrow` 横/竖向流程箭头、`direction_triangle` 涨跌方向三角、`bubble` 带尖角气泡（指向图表上具体元素，比漂浮说明文字更清楚指向关系）、底部橙色`band`结论条
- **框的内边距按 `tight_box`/`bubble` 默认的 `pad_ratio=0.25`（框≈文字125%大小）收紧，不要留大片空白显得松散**（470期教训：初版框框留白太多、用户反馈"显得很拥挤"——注意留白多≠不拥挤，元素之间的间距不够、单个框又占地方，反而更挤；框本身收紧后，元素间距才有地方喘气）
- **多格/多行布局的坐标必须按每格实际行数动态计算，不能对不同行数的格子套用同一套固定偏移**（459期教训：四宫格里唯独一格文字是两行，仍用其他单行格子的固定 y 偏移，导致标签和数值压在一起；改用 `tight_box` 或按行数算 `start_y` 就不会有这问题）
- 图内主标题用大纲 H3 原文（超长可精简不改意思）
- **图内引号一律用中文弯引号（左“右”），不用英文直引号（"）**（470期教训：初版用了英文直引号，被用户指出要改成中文引号；思源黑体对中文弯引号有正常字形，不会显示缺字方块）
- **设计图图内不放"图片来自AI…"标注**（用户2026-07-10明确要求：`ai_tag()` 只给走势图兜底用，设计图不调用；飞书caption照旧统一加）——**这条规则容易在改图时被漏掉**（470期实录：第一版正确遵守，改图时手滑又调用了 `ai_tag()`，被用户抓到才删掉），每次改图前对照这条清单过一遍，不要凭上一版的记忆直接改
- 引用真实人物（如书籍作者头像）**必须找可商用授权来源**（Wikimedia Commons 等 CC-BY-SA/公共领域图片），头像圆形裁剪+品牌橙描边+姓名小字标注；禁止用无授权来源的名人照片
- `save()` 自动产出 `*_thumb.png`（480px≈手机1/3屏观感）并校验字号下限
- **成品图和缩略图都要 Read 目检，改完图也要重新目检一遍再交付**（470期教训：改完文字/加完头像后直接发给用户，没有重新看一眼缩略图，结果四宫格里两行文字那一格压字没发现，被用户抓到）：缩略图上一眼懂主题、关键数据清晰、没有文字重叠或溢出框外才算过；不过就减字/加大字号/拆页/改用 `tight_box` 动态布局再验，并对照 design_spec.md 第六节清单逐条过
- **自定义网格/多行布局（如N等份小方块、多行卡片）必须手动核对总高度是否超出1080画布**：`save()` 只校验字号下限，不校验元素是否越界或重叠。468期"方案2定投20份"第一版用4行×190px格子，累加高度把底部结论条整个推出画布之外，缩略图上直接看不到结论条，肉眼目检才发现；布局前先算好 `起始y + 网格总高度 + 结论条高度` 是否留在1080以内。
- 渲染脚本存 `outline_NNN/`，文件名 `NNN设计_P页_主题.png`

#### ⚠️ 验收标准是"好看"，不是"没出错"（471期，这次栽得最狠）

用户原话：**"不是没有溢出就行了，要有最基本的审美你懂吗，就像睡觉，有一个超级大的床，但是所有人都挤在右侧角落，这是不正常的"**。把"不溢出、不重叠"当合格线是错的——471期照这个标准交付了三角形和文字之间空 240px 死空白、内容全挤在卡片上半部而下半部大片空白的图，被连续打回。

1. **留白要量、要对称**，不能只判断"装得下"：
   - 元素成组时，按**最长那行**算组宽，整组居中，核对**左右留白相等**（471期：三角形+文字作为一组居中后，左右各 120px）
   - 卡片内容垂直居中，核对**上下留白相近**（471期修好后是 79/83px）
   - 画布层面核对**上留白 vs 下留白**不要一头沉（471期：上 53px / 下 90px）
   - 内容少就把容器**改小**，不要把两行字摊在 570px 高的卡片里
2. **缩略图目检不够，必须拉原图量像素**。471期两次栽在这：租售比图"2% / 年"底边超出卡片 9px、折现法右卡最后一行余量 −1px，`*_thumb.png` 上完全看不出来。硬流程：
   - **渲染前**：`font(...).getlength(text)` 逐条量文字宽度 vs 容器可用宽度（容器宽 − 左右内边距），列出「余量」，有负数就先改
   - **渲染后**：`d.textbbox((x,y), text, font=..., anchor=...)` 量实际像素上下边界 vs 容器边界，算出上下余量
   - 两步都过了再 Read 原图（不是缩略图）目检
3. **多栏图要逐栏检查，不能只看一栏**：471期左栏空得离谱、右栏正常，只看右栏就放过了。
4. **胶囊/标签这类按等分排布的元素，宽度必须按文字长度动态算**，不能等分（471期"各省会城市"5个字把等分胶囊顶穿）。
5. **说"已改好"之前，对着用户逐条要求核一遍改动清单**。471期实录：用户圈了空白和溢出两处，我只改了标签宽度就回复"已改好"，被反馈**"图片没有任何变化，你改了啥，不要敷衍我"**。改了什么、没改什么，要能逐条对上。

## 常见变更请求的处理

- 「换成XX指数」：改代码重取数重画，删旧图重插，图例/注释同步改
- 「加个月度涨跌幅表」：chart_helpers 里 `monthly_returns` + `add_table`，表随图合成一张PNG
- 「说明文字统一改成…」：不用删图，PATCH caption 即可（见 feishu_ops.md）
- 用户手动挪过图（如两版样式并排进了grid）：改caption不影响排版；删旧图前先确认块的实际parent
